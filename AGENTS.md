# Правила работы с репозиторием и внешними форками

1. **Изучение документации и аудит:** Перед любыми правками всегда читай `README.md` и папку `docs/`. Сначала проведи аудит задачи и объясни пользователю простым русским языком, как сейчас устроен этот участок кода и нужен ли вообще фикс, прежде чем писать код.
2. **Безопасность веток:** Никогда не правь ветку `main` напрямую. Перед любой задачей создавай новую ветку (`git checkout -b <название_задачи>`).
3. **Умный поиск (`gh`):** Для поиска готовых решений в апстриме (`Marvisak/VIctory`) и соседних форках используй утилиту `gh` (`gh pr list`, `gh pr view`, `gh issue list`). Переноси только конкретные проверенные изменения в отдельную ветку.
4. **Экономия контекста («Эстафета»):** Веди в корне файл `HANDOFF.md` с текущим статусом, списком шагов и результатами замеров. Выполняй строго один шаг из плана за раз, обновляй `HANDOFF.md` и останавливайся для отчёта пользователю.
5. **Защита от перерасхода токенов:** Никогда не пытайся читать бинарные файлы (`.exe`, `.dll`, `.rpf`) как текст — используй для этого инструменты реверс-инжиниринга и встроенные флаги отладки проекта.
6. **Обязательная проверка:** После любого изменения кода запускай `cargo check --workspace` и `cargo test --workspace`. Если сборка падает — чини сразу.

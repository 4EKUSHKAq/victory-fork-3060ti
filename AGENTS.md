# Правила работы с репозиторием и внешними форками

1. **Изучение документации и аудит:** Перед любыми правками всегда читай `README.md` и папку `docs/`. Сначала проведи аудит задачи и объясни пользователю простым русским языком, как сейчас устроен этот участок кода и нужен ли вообще фикс, прежде чем писать код.
2. **Безопасность веток:** Никогда не правь ветку `main` напрямую. Перед любой задачей создавай новую ветку (`git checkout -b <название_задачи>`).
3. **Умный поиск (`gh`):** Для поиска готовых решений в апстриме (`Marvisak/VIctory`) и соседних форках используй утилиту `gh` (`gh pr list`, `gh pr view`, `gh issue list`). Переноси только конкретные проверенные изменения в отдельную ветку.
4. **Экономия контекста («Эстафета»):** Веди в корне файл `HANDOFF.md` с текущим статусом, списком шагов и результатами замеров. Выполняй строго один шаг из плана за раз, обновляй `HANDOFF.md` и останавливайся для отчёта пользователю.
5. **Защита от перерасхода токенов:** Никогда не пытайся читать бинарные файлы (`.exe`, `.dll`, `.rpf`) как текст — используй для этого инструменты реверс-инжиниринга и встроенные флаги отладки проекта.
6. **Обязательная проверка:** После любого изменения кода запускай `cargo check --workspace` и `cargo test --workspace`. Если сборка падает — чини сразу.
7. **Тщательность и A/B-контроль:** Вносить только по одному логическому изменению за шаг; перед переносом чужого кода построчно сверять индексы дескрипторов, root-таблиц и лимиты 8 ГБ VRAM; если замер после правки показывает падение FPS или новые визуальные артефакты — немедленно откатывать правку и разбирать причину.
8. **Мониторинг и перенос наработок:** В начале каждого раунда проверять все **7** репозиториев звёздного списка — `fxceless/victory-fork`, `Marvisak/VIctory`, `stellarr-studio/kelvaroq`, `Belobug/VIctory-Belobug-AMD`, `uiliannn/VItoriaBr`, **`xcl-dev/xcl`** и **`zortos293/XSEmu`** — на новые полезные фиксы CPU/VRAM/рендера (через `gh`, не `git fetch`) и включать их в план раунда. Лицензии: `xcl` — GPL-2.0, **только идеи/факты/цифры, код не переносить**; `XSEmu` — третья линия мониторинга (GPL-2.0-only заявлена, но 6 файлов GPL-3.0-or-later с provenance — перенос только из них и с provenance-нотой). Для каждого кандидата фиксировать номер PR/коммита, затронутые файлы, риск и ожидаемый эффект; переносить только проверенные изменения с A/B-замером.
   **NVIDIA-линия (с раунда 10):** дополнительно проверять NVIDIA-ориентированные деревья — `trustno1-coder/VIctory-NVIDIA`, `readmet3xt-lab/foxhound`, `Steenax6/VIctory-NVID`, `Xeltax/VIcky`, `101Leafy/victory-leafy`, `Fayberr/Victory-United` — на фиксы конкретно под NVIDIA (водные плиты, view-heap лимит 1 000 000, wave64/32-lane, AV в heap_direct_texture_reads, native 1440p, DLSS/Streamline). Чужой скомпилированный **exe не запускать** — только исходники/доки/диффы; перенос кода — с provenance-нотой (репозиторий + коммит + файл) и A/B-замером. **Обязательный скан свежих PR апстрима** `Marvisak/VIctory` в каждом раунде: `gh pr list -R Marvisak/VIctory --state open --limit 100` (сортировать по свежести/релевантности), отбирать только те, что чинят наш профиль (NVIDIA/8 ГБ VRAM/descriptor heap/wave32), и переносить с проверкой сборки и тестов.
